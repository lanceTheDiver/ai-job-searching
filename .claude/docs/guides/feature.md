# Feature 开发流程

实现新功能的标准流程。开始前请先阅读 [AGENTS.md](../../AGENTS.md) 了解技术栈和规范。

## 开发步骤

### 1. 理解需求
- 明确功能需求和预期行为
- 识别边界条件和特殊情况
- 确认 UI/UX 要求

### 2. 检查现有架构
- 查看相关的现有代码
- 了解当前的架构模式
- 识别可复用的组件和逻辑

### 3. 识别受影响的部分
确定需要修改或创建的：
- 后端 API（`app/api/`）
- 前端服务层（`lib/services/`）
- UI 组件（`components/` 或 `app/`）
- 类型定义
- 状态管理

### 4. 制定实施计划
创建清晰的实施步骤：
- 列出需要创建/修改的文件
- 确定开发顺序
- 识别潜在风险点

### 5. 实现后端
如果需要后端支持：
- 在 `app/api/` 创建 API Routes
- 实现服务器端逻辑
- 处理错误情况
- 添加必要的验证

### 6. 定义类型
- 在适当位置定义 TypeScript 类型
- 确保类型定义清晰准确
- 前后端类型保持一致

### 7. 实现前端服务层
- 在 `lib/services/` 创建 API 调用封装
- 实现错误处理
- 添加必要的数据转换

### 8. 实现 UI 组件
- 创建必要的 React 组件
- 使用 Tailwind CSS 和 shadcn/ui
- 实现状态管理（优先本地状态）

### 9. 运行测试
```bash
# 运行 lint 检查
pnpm lint

# 类型检查
pnpm tsc --noEmit

# 测试运行
pnpm dev
```

### 10. 审查变更
- 检查代码是否符合项目规范
- 确认没有引入不必要的依赖
- 验证功能完整性
- 检查边界条件

## 示例：添加"用户资料"功能

```
1. 需求：显示和编辑用户资料
2. 检查：components/ 中有类似的表单组件
3. 受影响部分：
   - app/api/user/profile/route.ts (新建)
   - lib/services/userService.ts (新建)
   - components/UserProfile.tsx (新建)
4. 计划：后端 API → 服务层 → UI 组件
5-8. 按计划实施
9. 测试功能和类型检查
10. 审查代码符合规范
```
